# 宣传片与发布物料（传）

目标：一条 20–30 秒的竖版宣传片（1080×1920），用工具的真实录屏剪成，拿去就能发。附带一个图标和一份文案。

## 1. 图标
- 1024×1024 的 PNG，用工具自己的渲染器画**核心交互的一瞬间**。比如光栅卡正在两张图之间交错切换的那一刻。
- 深色或品牌渐变底，加一圈柔光；主体略微倾斜，更有动感。
- 缩到 64px 还能认出来：别塞太多小字。

### 上架封面（小红书小工具后台，3:4）
- 1080×1440：上方大字卖点加一行胶囊副标题，中间放 3 张成品呈扇形摆开，底部放 3 个卖点标签。
- 3 张成品要用**不同题材**的照片（人物、宠物、美食），让人一眼看出什么都能做。
- 渲染器加一个 `transparent` 选项，只画卡片和主体、不画背景，方便合到新背景上，不会出现接缝。
- 大标题按"宽度 ≤ 画布宽 − 2×110px"自动缩小字号，两侧必须留白。
- 图标是 1:1，照片里只放一张卡片，主体略微倾斜；缩到 64px 时还要能认出来。

## 2. 录屏
1. 写一个 `scenario.js`，参考 `scripts/scenario.example.js`：
   - 每个镜头开头调一次 `mark('key')`；
   - 用 `tap`、`drag`、`pickFiles` 操作页面；
   - 演示用的照片要用用户自己的。
2. 录制：
   ```
   node scripts/harness.js record http://localhost:8000/index.html rec/ scenario.js
   ```
   - 视口 360×640 按 3 倍缩放，用 CDP screencast 录成 1080×1920 的 JPEG 帧。不要用 Playwright 的 recordVideo，太糊。
   - 会自动显示一个半透明手指光标；如果页面上有 `window.Sfx.play`，还会自动记录每次音效的时间。
3. 录屏时操作会变慢，帧率也低。合成时按段变速就行，不用让录制本身追求实时。
4. 有 AI 模型时，在第一个 `mark` 之前先预热模型（`page.evaluate` 跑一次识别）。识别这类长时间等待的段，用 `mark_offsets` 把起点挪到出结果前一刻。
5. 宣传片演示要用"效果最好"的那张照片。比如主体顶到照片上沿时就出不了框，换一张主体四周有空间的。

## 3. 合成
配置文件 `promo.json`，参考 `scripts/promo.example.json`：
- **`segments`**：每段写明起止 mark、目标时长、主字幕（≤16 字）和小标签。
- **`mark_offsets`**：用来跳过页面切换时的空白帧，或者让首页多停一会儿。
- **结尾卡**：工具名、两行副标题，加上图标。
- **口播（可选，推荐逐段）**：
  - 每段一条音频：顶层写 `"vo_dir": "vo"`，文件按 `01.wav`、`02.wav`… 对应第 1、2… 段，结尾卡用 `end.wav`；也可以在单段里写 `"vo_file"`。
  - 每段的 `"vo"` 写这句口播的文字（结尾卡用顶层 `"end_vo"`），用来生成 SRT 字幕。
  - **画面迁就声音**：不加速人声，改画面。`vo_fit` 两种模式：
    - `tight`（默认）：段长跟着口播走，说完就切，再取整到半拍（`bpm` 默认 100），镜头切在拍子上，句间停顿统一在 0.4～0.7 秒；某段画面需要多停，就给它设 `min_dur`。
    - `stretch`：只有口播比目标时长长时才拉长，其余保持 `dur`。
    - 开口前留 `vo_lead`（默认 0.12 秒），说完留 `vo_tail`（默认 0.3 秒）。
- **BGM（可选）**：`"bgm": "music.mp3"` 用外部配乐（不够长自动交叉循环，结尾 1.5 秒淡出）；不写就用代码合成的 lo-fi 律动（电钢琴和弦 + 低音 + 轻鼓，速度跟 `bpm` 一致）。配乐要确认能商用。
  - 音频首尾的静音会自动裁掉，所以 TTS 或录音前后带空白也没关系。
  - 旧写法仍然可用：`voice` 填整段录音，`voice_offset` 填开始时间。

运行：
```
python3 scripts/compose_promo.py promo.json
```
脚本会打印每段的变速倍数。超过 12 倍的段，画面会跳得很厉害，回去调整脚本或目标时长。
有口播时还会打印每段的口播时长，标出「为口播拉长」的段；画面放慢到 0.45 倍以下会报警，说明这句口播太长、录屏太短，缩短口播或多录几秒。
有口播时额外输出：`<out>_vo.json`（每段起止、开口时间、口播时长、变速倍数）和 `<out>.srt`（口播字幕）。

### 口播的验收标准
- 每句口播都落在自己那段画面里：开口时间 = 段起点 + vo_lead，说完到下一段至少留 vo_tail；
- 没有被截断的句子，结尾卡口播在结尾卡上说完；
- 成片响度 -16 LUFS（±1），真峰值 ≤ -1.5 dBTP（脚本用两遍 loudnorm 自动做到）；
- 有人声时配乐自动压低约 10 dB（`music_gain` 0.55 → `music_duck` 0.16），句内短停顿不回弹；
- 品牌词和工具名读音正确：抽听每段开头。

## 3b. short-ppt 版（无口播时默认）
像做 PPT 一样把录屏讲清楚：左上角一个接一个的关键词节点，底部短字幕，粗宋体 3:4 封面。排版交给 [short-ppt skill](https://github.com/mingjuntx/short-ppt)，马良负责剪节奏和配乐。2026-10-30 打冰激凌模拟器上用户认可这一版（「目前可以」）。有口播的宣传片仍走上面的 `compose_promo.py`。

**节奏：约 3 秒一个节点**
- 一个节点 = 一个动作或卖点，输出时长 2.4～3.5 秒；30 秒左右的片子 10～11 个节点。第一版按 6～20 秒一个节点做，用户嫌「节奏有点长」。
- 长动作（往上叠、拖着走）按 1.3～1.8 倍加速剪进一个节点，不要拖成两三个节点；节点之间硬切。
- 节点标题 3～6 字（「越高越抖」「收尖量高度」），副标题 ≤10 字补一句细节（「量出 19.7cm」）。
- 底部字幕是口语短句，≤14 字一行；**抽屉、弹窗、卡片打开的节点不出字幕**（字幕会压在抽屉内容上，节点标题已经讲清楚了）。字幕结束时间要卡在抽屉弹出之前，抽帧确认。

**配乐：要有律动，不要单调铺底**
- 第一版只有一个大三和弦长铺 + 音效，用户说「bgm 有点单调」。改成 116 BPM 的律动：底鼓、军鼓、踩镲、贝斯、反拍和弦，和弦走 C–G–Am–F，每两小节一句旋律；第一小节只放踩镲和和弦当前奏，结尾停在主和弦长音上。
- 「塌了 / 翻车 / 失败」这种瞬间用 `drop_at` 让鼓和贝斯停一拍再进，比一直铺着更有戏。
- 交互音效按录屏打点叠上去，加速段同一种音效间隔不小于 0.22 秒，否则太密。
- 自动口播 + 更好的配乐由另一条线在做，做好后接到这里。

**做法**
1. 录屏同第 2 节（`harness.js record`），mark 打在每个动作开头。
2. 写 `shortppt.json`（参考 `scripts/shortppt.example.json`），每段写 `from` / `to`（秒数、mark 名或「mark±秒」）、`speed`、`title`、`sub`、`cap`（抽屉段写 `null`）。
3. `node scripts/shortppt_cut.mjs shortppt.json`：按节点重剪、合成配乐和音效，输出 `source.mp4`（默认放大到 1080 宽，录屏帧常常只有 390 宽）、`captions.srt`、`chapters.json`。打印的节点时长不在 2～4 秒会报警。需要 ffmpeg：环境变量 `FFMPEG_BINARY`，或 PATH 里的 ffmpeg（short-ppt 装好后自带一个 imageio-ffmpeg）。
4. 按 short-ppt 的 README 装好依赖、跑 `configure_fonts.py`，然后：
   ```
   python scripts/chapters.py --plan chapters.json --duration <秒数>
   python scripts/render.py --input source.mp4 --output-dir final --title "第一行\n第二行" --srt captions.srt --chapters chapters.json --style style.json
   ```
   `style.json` 从 short-ppt 默认导出的那份改一处：`"subtitle_bottom": 0.19`（默认 0.24 的字幕正好压在录屏里的手指光标上）。
5. **封面单独做**：默认按 `--cover-time` 居中裁 3:4，竖长录屏会把主体顶部切掉（冰激凌尖没了）。改成截录屏上半屏（带上分数 / 高度这类读数），两侧用同一帧放大模糊补成 3:4，存成 PNG 后 `render.py --input cover-src.png --cover-only`。
6. 自查：每个节点中间抽一帧拼图，看节点标题、字幕、手指光标、抽屉有没有互相压住；再抽抽屉弹出前后的帧，确认字幕已经消失。
7. 发小红书前不用 remux：ffmpeg 出的是普通 MP4。

## 4. 镜头建议（光栅小卡机，29 秒）
| 镜头 | 时长 | 字幕 |
|---|---|---|
| 首页自动演示 | 3.0s | 做了个会变的光栅小卡 |
| 选照片 | 2.4s | 选几张喜欢的照片 |
| 生成 | 1.3s | 一键压成光栅卡 |
| 核心交互 1 | 4.2s | 左右歪一歪 → 换一张 |
| 核心交互 2 | 3.4s | 上下歪 → 虚焦再对焦 |
| 换皮肤 | 4.6s | 6 种卡面随手换 |

| 关注 | 2.2s | 喜欢就关注一下作者 |
| 分享 | 2.2s | 一键发笔记 |
| 结尾卡 | 3.2s | 工具名 + 搜一搜就能玩 |

## 5. 声音
- 没有口播时，用代码合成一段轻快配乐：和弦铺底、琶音、低音。再在录屏记下的时间点叠加交互音效：咔哒、啵、铃。
- 有口播时：
  - 用户本人的录音，先帮他优化节奏：切掉气口、压缩长停顿，再按句切成 01.wav、02.wav…；
  - 声音克隆 / TTS 生成的口播，直接一句一个文件放进 `vo_dir`；
  - 合成脚本负责对齐画面、压低配乐、统一响度、出 SRT 字幕。
- 合成的 AI 口播要加显式标识，并提醒用户发布时勾选「含 AI 合成内容」。

## 6. 自查
在每段中间抽一帧，拼成一张图自己看一遍，确认三件事：没有空白页、字幕没被挡住、结尾卡完整。

## 7. 文案
- 3 个标题备选（≤20 字）。
- 正文：一句情绪开头，分点加 emoji 写玩法，结尾抛一个问题，引导大家去评论区晒图。
- 写明「搜「工具名」就能玩」和版本要求。
- 话题标签 6–10 个。
- 用户需要笔记图时，再出 4–6 张 1080×1440：
  - 封面：大字卖点、成品呈扇形摆开、卖点标签；
  - 2–3 张工具实际导出的图；
  - 一张皮肤一览；
  - 一张特色功能对比。
